# 看我笑話現場投票

最新揭曉流程：投票中不公開票數或領先隊伍；截止立即生效，中央 QR 轉為 3、2、1 縮小倒數，接著中央方塊消失、票數由零跑到最終值，完成後才公布勝隊並從勝隊區塊噴出三波彩帶。揭曉期間 Enter 暫停，完成後可開始下一輪。手機不提前顯示票數或贏家，請觀眾看大螢幕。重整已結束畫面直接顯示結果，不重播動畫。減少動態效果時保留倒數文字與結果。

> 2026-10-16 正式版更新：已接上既有 Supabase。投影固定網址為 `https://allen365apple.github.io/jokes-on-me/live-vote/`，觀眾固定網址為 `https://allen365apple.github.io/jokes-on-me/live-vote/vote.html`。Enter 依序開放、截止、清票並開放下一輪。手機選隊打勾後按「投票」才送出，截止前可更換隊伍並按「確認改投」，後端以同一筆選票原子替換，不增加總票數。截止後禁止改投。

> 按 T 或右上角「測試」，輸入兩隊票數後測試倒數、跑票及彩帶；Esc 或畫面頂端按鈕返回正式畫面。測試僅作用在本機顯示，不呼叫正式投票或控制指令；測試期間 Enter 不操作正式場次，退出時恢復最新正式狀態。狀態以灰字顯示於左上角「現場投票」後，右上角保留低調控制列，觀眾連結移入 C 控制台。

> 投影預設上下滿版。↑／↓ 以每次 2vh 移動整個畫面，可長按；往上移會空出下方，往下移會空出上方。Home 歸位，上下各最多移動 80vh；控制台也可調整位置。輸入欄位或對話框開啟時不攔截方向鍵，位置調整不影響選票或投票開關。

> 按 Q 開啟右上角 QR 小面板，可用滑桿即時調整中央 QR 的大小與上下位置，或按眼睛暫時隱藏／顯示；預設置中，設定只記在操作端本機。QR 放大時受視窗上限保護，避免超出畫面。勝利時播放指定的本機 MP3 音效，預設開啟；可在 C 控制台試聽、調整音量，按 M 靜音。瀏覽器需先透過 Enter、M、T 測試或試聽按鈕等操作解鎖播放。
>
> 控制端按 C，輸入本機 `operator.local.txt` 的私有操作碼後啟用。操作碼不在程式碼、QR、公開網址或 Git 裡。後端使用 `supabase-live.sql` 與 `room-store.mjs`，不需要匿名 Auth，因此不受共用 Wi-Fi 的匿名登入數限制。此識別方式符合本案輕量防重複需求，不能視為嚴格一人一票。
>
> 以下為初版排練架構與安裝歷史說明，與新版衝突處以上方正式版操作為準。

雙隊 PK、整場最後投一次，預估最多 150 位觀眾。包含投影控制頁、手機投票頁、本機排練模式與 Supabase 正式投票。

## 目前狀態

- 線上正式投票使用固定 Supabase 房間，投影與觀眾手機透過同一公開網址流程同步；不使用匿名 Auth。
- 本機排練可用：開始／截止、模擬加票、勝負效果、隊伍設定與手機頁試投。排練資料只在同來源瀏覽器同步，不會送進正式房間。
- 每輪由操作端 Enter 開始、Enter 截止並揭曉、揭曉完成後再按 Enter 清票並開啟下一輪。
- 正式演出前仍須確認操作端連線狀態、QR 可掃描、至少兩支手機成功投票與改投，並測試截止及音效。
- 沒有啟用付費服務，也沒有刪除既有專案檔案。

線上排練：[看我笑話現場投票](https://allen365apple.github.io/jokes-on-me/live-vote/)。也可從[看我笑話工具箱](https://allen365apple.github.io/jokes-on-me/)的「現場演出工具」進入。

## 本機開啟

在這個資料夾執行（需已安裝 Node.js）：

```sh
npm start
```

開啟 <http://127.0.0.1:8765/live-vote/>。預覽只綁定本機，不會開放外部或其他手機連線。關閉預覽用 Ctrl+C。若連接埠已被使用，可執行 `LIVE_VOTE_PORT=8766 npm start`。

這是多頁網站，請透過本機 HTTP 服務開啟，不能直接雙擊 HTML 使用 `file://`。

### 先試一次

1. 首頁預設進入「排練・模擬票數」，八位演員已設定好。
2. 按 Enter 開放投票。按 1／2 為左／右隊加一票；控制台也能各加十票。
3. 「開啟觀眾畫面」可在同一瀏覽器試投。可另開分頁保留投影；排練只能在同來源、同瀏覽器同步。
4. 選一隊，再按「投票」。重整仍顯示已投；截止前可選另一隊，再按「確認改投」。
5. 回投影頁再按 Enter 截止。勝隊亮場、彩帶並播放已解鎖的勝利音效。
6. 揭曉動畫完成後按 Enter 清票並開始下一輪；本機排練歷史與線上正式場次分開。

### 快捷鍵

| 按鍵  | 功能                                   |
| ----- | -------------------------------------- |
| Enter | 開放／截止；揭曉完成後清票並開始下一輪 |
| C     | 控制台                                 |
| F     | 全螢幕（裝置支援時）                   |
| Q     | QR 大小與顯示控制                      |
| M     | 開關勝利音效                           |
| 1／2  | 排練左／右隊各加一票                   |
| Esc   | 關閉控制台                             |

長按不重複觸發；主要狀態操作短時間連按有保護。設定面板、文字輸入及輸入法組字時暫停快捷鍵。控制台其他項目可用 Tab、方向鍵與 Enter 操作。

## 視覺與設定

- 兩隊色塊固定左右分區，中央斜切 VS；大票數為真實整數，不播放虛構的遞增數字。
- 兩根直立票柱有相同基準與繪圖高度。預估 150 人只決定刻度，不限制有效票上限。
- 投影主標題為「今天哪一隊最有趣？投票吧！」；手機投票頁另有品牌小字。
- 控制台可改隊名、顏色、1～8 位成員、順序、顯示名字、既有演員或 HTTPS 頭像網址、裁切位置。
- 頭像沿用 `../love-improv/profiles/thumbs/`，失敗則以姓名占位。
- 開放後鎖定陣容；下一場另建新場次。設定與選票快照留在原場。
- 裝置偏好包括字級、上下位置、QR 大小／上下位置／顯示、音效開關／音量、彩帶效果、減少動態效果；存於 localStorage。
- 保留上方 45vh、下方 100vh 捲動留白，初次載入定位到看板。
- 勝利音效使用指定的 MP3 檔，預設開啟；需先經操作端手勢解鎖播放。
- 平手兩隊亮場；零票不慶祝。已結束頁重整不重播音效。

## 線上後端與操作安全

- 線上正式頁使用 `supabase-live.sql` 建立的固定房間；`supabase-setup.sql` 是較早期的場次制方案，**不要拿它覆蓋或套用到目前正式資料庫**。
- `config.mjs` 只放 Supabase 公開連線網址與 publishable key；絕不可放 secret/service-role key 或操作碼。
- 操作端以私有操作碼呼叫資料庫函式；不要把操作碼寫進程式碼、公開檔案、QR 或 Git。觀眾不需要建立帳號。
- 觀眾瀏覽器以本機 UUID 作為每輪識別；同一瀏覽器重送或改投會沿用同一筆選票。此為輕量防重複，不防無痕模式、清除資料或換瀏覽器。
- 投票、改投、截止及最終計票在資料庫交易中處理；截止時以有效選票重新計算總數。控制指令有識別碼以避免網路重試重複執行。
- 投影端訂閱票數狀態；手機端只接收場次狀態訊號並定期核對，避免每張票都廣播給所有觀眾。
- 自動測試模擬 150 個投票身分，不等同於 150 支真實手機同時連線。正式演出前，仍要以場地網路及實際手機完成 QR、投票、改投、截止、重整與音效驗收。

## 測試

```sh
npm install --ignore-scripts
npm run check
npm test
```

測試使用 Node.js 內建 test runner 與記憶體中的 PGlite PostgreSQL；不連外、不寫正式資料、不刪檔。

涵蓋純邏輯、150 身分重送、實際 SQL 函式、RLS、控制權限、截止重算、歷史隔離、訊號節流設計、過期同步回應、備援、本機預覽檔案白名單與音效播放控制。

PGlite 並不是完整 Supabase 服務，測試不涵蓋 GoTrue 登入、Realtime 服務、真實多連線鎖競爭、網路尾延遲或真實投影機。這些列在上線前驗收，不宣稱通過。

## 檔案

| 檔案                        | 用途                                      |
| --------------------------- | ----------------------------------------- |
| `index.html` / `stage.mjs`  | 投影、控制台、排練                        |
| `vote.html` / `vote.mjs`    | 手機選隊、確認、收據                      |
| `core.mjs`                  | 驗證、狀態、比例與鍵盤規則                |
| `store.mjs`                 | 排練儲存、Supabase 與同步                 |
| `ui.mjs` / `style.css`      | 共用畫面與效果                            |
| `音效素材 001 戰鬥勝利.mp3` | 勝利時播放的指定音效                      |
| `config.mjs`                | 前端公開連線設定                          |
| `supabase-live.sql`         | 目前固定房間的權限、交易與計票            |
| `supabase-setup.sql`        | 舊版場次制 schema；勿套用於目前正式資料庫 |
| `dev-server.mjs`            | 僅開放頁面素材的本機預覽                  |
| `vendor/`                   | 固定版本 Supabase SDK 2.118.0 與 MIT 授權 |
| `tests/`                    | 不連線正式服務的自動測試                  |

不需打包即可用靜態主機提供頁面。正式交付需包含以上前端檔案、`vendor/supabase.js`、原有 QR 程式與演員縮圖；不要把 `node_modules`、測試、SQL、私有文件或其他專案後台一起公開。QR 使用既有 Kazuhiko Arase MIT 程式，不向第三方 QR 服務傳送場次網址。

## 發布前敏感資訊檢查

排練版發布前已檢查新增內容，連線設定為空，沒有實際金鑰、管理密碼或新內部服務連線設定。後續推送／部署前，仍必須主動檢查：API 金鑰與 Token、客戶名稱與合作關係、內部 URL、員工真名、內部頻道／團隊結構。預期公開的演出藝名與素材也應確認授權。

尤其不能將其他主持人頁面或私有設定連帶打包；本機預覽伺服器已使用資產白名單，但公開部署仍須另行審查實際發布內容。
