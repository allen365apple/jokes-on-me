# 看我笑話現場投票

雙隊 PK、整場最後投一次，預估最多 150 位觀眾。包含投影控制頁、手機投票頁、排練模式，以及待安裝的 Supabase 後端。

## 目前狀態

- 本機排練可用：開始／截止、模擬加票、勝負效果、隊伍設定、手機頁試投與歷史紀錄。
- 排練版已透過 GitHub Pages 發布，工具箱首頁已加入入口。正式連線程式與 SQL 已完成；**尚未連接或修改線上 Supabase，仍不能跨裝置收正式選票**。
- 正式啟用前，需要確認後端專案、匿名登入、管理員權限及場地網路測試。
- 沒有啟用付費服務，也沒有刪除既有專案檔案。

線上排練：[看我笑話現場投票](https://allen365apple.github.io/jokes-on-me/live-vote/)。也可從[看我笑話工具箱](https://allen365apple.github.io/jokes-on-me/)的「現場演出工具」進入。

## 本機開啟

在這個資料夾執行（需已安裝 Node.js）：

```sh
npm start
```

開啟 <http://127.0.0.1:8765/live-vote/>。預覽只綁定本機，不會開放外部或其他手機連線。關閉預覽用 Ctrl+C。若連接埠已被使用，可執行 `LIVE_VOTE_PORT=8766 npm start`。

這是多頁網站，請透過本機 HTTP 服務開啟，不能直接雙擊 HTML 使用 `file://`。

### 先試一次

1. 首頁預設進入「排練・模擬票數」，八位演員已設定好。
2. 按 Enter 開放投票。按 1／2 為左／右隊加一票；控制台也能各加十票。
3. 「開啟觀眾畫面」可在同一瀏覽器試投。可另開分頁保留投影；排練只能在同來源、同瀏覽器同步。
4. 選一隊，再按「確認投票」。重整仍顯示已投，不能改票。
5. 回投影頁再按 Enter 截止。勝隊亮場、彩帶，音效可自行開啟。
6. 按 C →「建立新場次」可繼續排練，不清除前場紀錄。

### 快捷鍵

| 按鍵  | 功能                       |
| ----- | -------------------------- |
| Enter | 開放／截止；已結束不再重開 |
| C     | 控制台                     |
| F     | 全螢幕（裝置支援時）       |
| Q     | 顯示／隱藏 QR 區域         |
| M     | 開關勝利音效               |
| 1／2  | 排練左／右隊各加一票       |
| Esc   | 關閉控制台                 |

長按不重複觸發；主要狀態操作短時間連按有保護。設定面板、文字輸入及輸入法組字時暫停快捷鍵。控制台其他項目可用 Tab、方向鍵與 Enter 操作。

## 視覺與設定

- 兩隊色塊固定左右分區，中央斜切 VS；大票數為真實整數，不播放虛構的遞增數字。
- 兩根直立票柱有相同基準與繪圖高度。預估 150 人只決定刻度，不限制有效票上限。
- 小字與標題使用指定的「看我笑話現場投票」「今天哪一隊最有趣？投票吧！」。
- 控制台可改隊名、顏色、1～8 位成員、順序、顯示名字、既有演員或 HTTPS 頭像網址、裁切位置。
- 頭像沿用 `../love-improv/profiles/thumbs/`，失敗則以姓名占位。
- 開放後鎖定陣容；下一場另建新場次。設定與選票快照留在原場。
- 裝置偏好包括字級、上方留白、音效開關／音量、彩帶效果、減少動態效果；存於 localStorage。
- 保留上方 45vh、下方 100vh 捲動留白，初次載入定位到看板。
- 勝利音效是本機合成的短促歡呼氛圍聲，不是付費或外部音檔。預設靜音；操作後才可播放。
- 平手兩隊亮場；零票不慶祝。已結束頁重整不重播音效。

## 正式 Supabase 設定（尚未執行）

請先確認要沿用哪個專案及其權限；不要直接從舊網站複製管理密碼或高權限金鑰。

1. 確認管理權限及目前資源用量。若沿用 `fwb-quiz` 的專案，先檢查既有 RLS：啟用匿名登入後，匿名使用者也屬於 `authenticated`，不能讓其他舊資料表因此被開放。
2. 在管理後台檢查並啟用 Anonymous Sign-Ins。此步會改變專案登入能力，須由擁有者確認。
3. 先在測試專案 SQL Editor 審閱並執行 `supabase-setup.sql`。使用 `jlv_` 前綴，新增四個資料表與相應函式，不清除其他資料。
4. 建立或選用一個正式管理員 Auth 帳號，再由可信任的資料庫管理介面將其 UUID 加入 `public.jlv_admins`。密碼由使用者自行設定，不能寫進公開程式。
5. 將該專案的 HTTPS Project URL 與 **`sb_publishable_` 公開金鑰**填入 `config.mjs`。不接受 service-role、secret key 或管理 Token。
6. 在 `?mode=live` 開啟投影頁，按 C 登入並建立新場次。URL 會固定包含場次 UUID。
7. 確認 `supabase_realtime` publication 已包含 `jlv_sessions`、`jlv_signals`。不要加入選票或管理員表。
8. 在公開發布前掃描敏感資訊並取得發布授權，再測正式 QR、至少兩部實體手機、重整和截止交界。

管理員資料例子（只在可信任 SQL Editor 執行，不放在前端）：

```sql
insert into public.jlv_admins(user_id)
values ('在這裡填入已確認的管理員 Auth UUID')
on conflict do nothing;
```

上述佔位文字不是可執行 UUID，請填入真實帳號 ID 後再執行；不要把帳號、密碼或 Token 貼進公開檔案。

### 150 人現場的必要檢查

查核日期：2026-10-16。服務額度會變動，上線時要重新查實際專案設定。

- 官方目前列出的匿名登入預設限制是**每個 IP 每小時 30 次**。150 位新觀眾若共用場地 Wi-Fi，不能直接使用這個預設值。需由擁有者確認合理的匿名登入限額與防濫用安排，並在同一出口 IP 進行集中加入測試。
- 若專案已要求 CAPTCHA，本版匿名登入沒有整合 CAPTCHA UI，需先規劃整合，不可為求方便擅自關閉既有保護。
- 核對 Realtime 同時連線、事件吞吐、資料庫及匿名 Auth 用量；同專案其他活動也會共用資源。需要升級或付費時先詢問使用者。
- 投影訂閱 `jlv_sessions` 的票數；手機只訂閱 `jlv_signals` 的開始／截止／陣容變動，避免每一票都廣播到 150 支手機。手機仍會定期查核狀態。
- 本機測試的 150 個資料庫身分並非 150 部真實手機同時連線，不能當作現場壓測已完成。

## 正式投票機制

- 匿名登入保存同一瀏覽器的身分；管理員與觀眾使用分開的 Auth storage key，管理員登出不會清掉觀眾身分。
- `(session_id, voter_id)` 唯一主鍵限制每場一票；身分取自伺服器 `auth.uid()`，不能由前端指定他人 ID。
- 重送回傳原選票，不能換隊；已截止仍能查回自己成功送出的票。
- 送票、設定、開始、截止共用場次資料列鎖。截止交易重算有效選票後才回傳最終結果。
- 公開可讀場次與彙總；觀眾只能讀自己的選票，不能直接寫選票、修改統計、改狀態或列出管理員。
- 推播斷線後啟用有分散時間與退避的輪詢；重新上線／回前景立刻核對，忽略舊版本回應。
- 網路逾時不假報投票成功；先恢復原選票狀態，再讓觀眾重試。不自動補投已結束的場次。
- 共用 Wi-Fi 不會被當作同一投票者。不防無痕模式、更換瀏覽器或清除瀏覽資料，符合本案的輕量防重複需求。
- 每個 QR 固定對應一場；掃舊 QR 不會自動跳到新場。排練及 loopback 本機頁不顯示誤導的可跨手機 QR。

## 測試

```sh
npm install --ignore-scripts
npm run check
npm test
```

測試使用 Node.js 內建 test runner 與記憶體中的 PGlite PostgreSQL；不連外、不寫正式資料、不刪檔。

涵蓋純邏輯、150 身分重送、實際 SQL 函式、RLS、管理權限、截止重算、歷史隔離、訊號節流設計、過期同步回應、備援與本機預覽檔案白名單。

PGlite 並不是完整 Supabase 服務，測試不涵蓋 GoTrue 登入、Realtime 服務、真實多連線鎖競爭、網路尾延遲或真實投影機。這些列在上線前驗收，不宣稱通過。

## 發布前敏感資訊檢查

排練版發布前已檢查新增內容，連線設定為空，沒有實際金鑰、管理密碼或新內部服務連線設定。後續推送／部署前，仍必須主動檢查：API 金鑰與 Token、客戶名稱與合作關係、內部 URL、員工真名、內部頻道／團隊結構。預期公開的演出藝名與素材也應確認授權。

尤其不能將舊 `fwb-quiz` 主持人頁面或私有設定連帶打包；本機預覽伺服器已使用資產白名單，但公開部署仍須另行審查實際發布內容。
